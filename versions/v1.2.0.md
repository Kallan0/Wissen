# Release Version v1.2.0

**Release Date:** 2026-09-04  
**Project:** Local AI-Powered Resume Builder  
**Version:** v1.2.0  

---

## 1. Overview
Version 1.2.0 addresses user data privacy and database transparency. It completely clears the temporary sample seed profile from ChromaDB (leaving the vector store at 0 items) and adds native **Resume PDF File Upload & Extraction**, allowing users to upload their real PDF resumes directly into the local vector database without external cloud exposure.

---

## 2. Changes Made & Files Modified

### A. Real Resume PDF Ingestion (`backend/rag/ingestion.py`, `backend/requirements.txt`)
- **Changes:**
  - Added `pypdf` dependency (`pypdf>=4.0.0`).
  - Added `IngestionService.ingest_pdf_file(file_bytes, filename)` to extract raw text across all pages from uploaded PDF resumes and segment them into overlapping semantic chunks with metadata tags.
- **Reason / Rationale:**
  - Enables users to directly upload their actual resume PDF instead of relying on any sample profile or manual data entry.

### B. Upload Resume REST Endpoint (`backend/main.py`)
- **Changes:**
  - Added `POST /api/knowledge-base/upload-resume-pdf` using FastAPI `UploadFile` and `File(...)`.
  - Validates file extensions, processes binary streams in memory, and returns updated vector database statistics.
- **Reason / Rationale:**
  - Provides a secure endpoint for the frontend to upload real PDF documents directly into the persistent ChromaDB store.

### C. Frontend Direct PDF Upload Card (`frontend/src/components/KnowledgeBase.tsx`, `api.ts`)
- **Changes:**
  - Added `uploadResumePDF(file: File)` to [`frontend/src/lib/api.ts`](file:///c:/Users/Joji/2026%20Exp/Resume_builder/frontend/src/lib/api.ts).
  - Added a dedicated "Upload Your Actual Resume (PDF)" card to [`KnowledgeBase.tsx`](file:///c:/Users/Joji/2026%20Exp/Resume_builder/frontend/src/components/KnowledgeBase.tsx) with a file picker and loading indicator.
- **Reason / Rationale:**
  - Delivers a one-click user experience for uploading and indexing real career documents.

### D. Complete Vector Database Reset
- **Changes:**
  - Completely erased the 24 sample profile items previously ingested from `sample_profile.json` during the setup verification test.
  - Verified ChromaDB state: `{'experiences': 0, 'skills': 0, 'projects': 0, 'education': 0, 'raw_documents': 0, 'total_items': 0}`.
- **Reason / Rationale:**
  - Clarified to the user where the previous data came from (it was a seed file from testing, NOT an LLM hallucination) and ensured their local database starts completely clean with 0 records.

# Release v1.13.0 — 2026-09-22

## Overview

Diagnosed the stopped QLoRA run as a Hugging Face authorization failure for the gated `meta-llama/Meta-Llama-3-8B-Instruct` repository. Dataset validation and CUDA checks pass; model weights were not loaded and training did not begin.

## Detailed changes

### `backend/finetuning/finetune_llama3.py`

- Added a gated-model access check before tokenizer/model loading and GPU allocation.
- Converts Hugging Face 401/403 responses into concise instructions to accept the model terms and authenticate the isolated training environment.
- Uses the locally installed `.venv-train\Scripts\hf.exe` CLI and never accepts or stores a token in repository files.

### `backend/finetuning/training_preflight.py`

- Added `--base-model` and a fail-closed `model.access` check.
- Added `--skip-model-access-check` for explicitly offline validation runs.
- Records the checked base-model identifier in the preflight report.

### Documentation and tests

- Added the exact secure login and identity-check commands to the next-steps plan.
- Added regression coverage for denied model access.
- Five targeted fine-tuning/preflight tests pass; the modified files also pass bytecode compilation.

## Manual action required

1. Accept the model terms in a browser while signed into the intended Hugging Face account.
2. Run `.\.venv-train\Scripts\hf.exe auth login` from the repository root.
3. Confirm the identity with `.\.venv-train\Scripts\hf.exe auth whoami`.
4. Rerun the training preflight and proceed only when `model.access` passes.

# Release v1.15.0 — 2026-09-22

## Overview

Verified access to the gated `meta-llama/Meta-Llama-3-8B-Instruct` repository and attempted the approved local QLoRA run. The complete 14.97 GiB checkpoint downloaded successfully, but Transformers correctly stopped before training because the 8B quantized model could not fit entirely in the RTX 4050 Laptop GPU's 6 GiB VRAM. No optimizer step ran and no partial adapter was produced.

The training path has therefore moved to a Google Colab T4 while retaining the same reviewed dataset, base model, QLoRA configuration, and untouched holdout gate.

## Colab T4 workflow

Replaced `backend/finetuning/fine_tune_colab.ipynb` with a current Hugging Face TRL/PEFT workflow:

- requires a CUDA GPU with at least 14 GiB VRAM;
- uses secure `notebook_login()` authentication and verifies gated `config.json` access;
- optionally mounts Google Drive and writes resumable epoch checkpoints there;
- accepts only `training_data.jsonl` and explicitly refuses `holdout_eval.jsonl`;
- verifies the exact approved dataset SHA-256 `72baab567553c43ec815db089905d23f108978a50039cffeb18e4bfc0d64d70d`;
- requires exactly 120 unique records with the verified candidate name and non-empty experience;
- creates a deterministic 108/12 internal loss-monitoring split;
- trains NF4 double-quantized Llama 3 8B with FP16, gradient checkpointing, and LoRA;
- resumes automatically from the newest Drive `checkpoint-*` directory;
- saves the adapter, tokenizer, package versions, base revision, metrics, configuration, and dataset hash;
- exports `resume-llama3-lora-adapter.zip` but deliberately does not merge or create GGUF before holdout evaluation.

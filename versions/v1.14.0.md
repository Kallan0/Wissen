# Release v1.14.0 — 2026-09-22

## Overview

Performed a conservative runtime and legacy-code cleanup while gated-model approval is pending. The work keeps active product features and fine-tuning data intact, removes only a proven-superseded trainer and regenerable artifacts, and reduces backend import latency substantially.

## Runtime improvements

### Lazy optional services

- `backend/rag/vectorstore.py` no longer imports or initializes ChromaDB during application import.
- Added a thread-safe lazy proxy with explicit public methods so existing callers keep the same interface.
- Chroma singleton construction is atomic: a failed optional import cannot leave a partially initialized global instance.
- `backend/pdf/generator.py` imports Playwright only during PDF generation.
- `backend/rag/ingestion.py` imports `pypdf` only during PDF ingestion.

Measured backend import time fell from approximately 2.5–6.8 seconds to approximately 0.8 seconds on the current workstation. ChromaDB remains unopened until the first knowledge-base operation.

### Async request handling

- `/api/health` checks Ollama and ChromaDB concurrently.
- `/api/tailor` runs profile loading and vector retrieval in worker threads.
- `/api/recommend-positions` and post-GitHub-sync statistics no longer block the event loop.

## Removed legacy and generated content

- Removed `backend/finetuning/train_lora.py`; it was superseded by the validated `finetune_llama3.py` implementation and contained incompatible/double-PEFT behavior.
- Removed unused direct runtime dependencies: LangChain, LangChain Community, and FastEmbed.
- Removed regenerable Python bytecode caches, root pytest cache, Next.js build output, and TypeScript incremental metadata.
- Three pre-existing Windows-locked pytest cache directories could not be removed safely and were left in place.

## Test-data safety

- `CHROMA_DIR`, `PDF_DIR`, and `SAMPLE_DIR` can now be overridden through environment variables.
- The E2E suite selects `backend/data/test_chroma_db` before importing the application, preventing it from clearing the real candidate knowledge base.

## Verification

- Backend import benchmark: approximately 0.8 seconds and `vector_store.is_initialized == False` immediately after import.
- Isolated ChromaDB smoke test: stats endpoint returned HTTP 200 and initialized the database only on first use.
- Fifteen non-E2E backend tests passed.
- Frontend production build passed; first-load JavaScript remained 116 kB.
- The full E2E attempt could not complete under the global Python environment because it does not have ChromaDB installed; the project backend environment has ChromaDB but does not currently include pytest. This is an environment separation issue, not a production-path failure.

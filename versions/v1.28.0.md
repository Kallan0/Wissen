# v1.28.0 - Retrieval recovery and non-blank resume safeguards

## Root causes

- Chroma attempted to load MiniLM from the user-level cache, where the tokenizer files were not readable. The collection query caught that exception and returned zero matches.
- The current knowledge base contains three recovered raw resume chunks but no structured experience, project, skill, or education records.
- The live Groq model identifier contained an extra slash (`openai//gpt-oss-20b`), causing cloud generation to fail and activate the sparse raw-document fallback.

## Changes

- Added a shared embedding factory that stores Chroma's `all-MiniLM-L6-v2` model under `backend/data/embedding_cache/onnx_models`.
- Preserved Chroma's persisted `default` embedding-function contract while redirecting its ONNX cache.
- Hybrid retrieval now catches dense-query errors separately and continues with normalized BM25 results, including verified documents when lexical overlap is zero.
- Corrected Groq defaults and the ignored live `.env` model identifier to `openai/gpt-oss-20b`.
- Raw-document profile reconstruction now extracts verified candidate name, email, and phone values without creating experience or project records.
- The non-LLM fallback extracts the existing professional-summary section from the uploaded resume instead of returning a completely blank document.
- Added a reusable cache warm-up command and regression tests for degraded dense retrieval and raw-document identity extraction.

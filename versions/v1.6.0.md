# Release v1.6.0 — 2026-09-21

## Overview

Added a repository-wide audit and a validated, reproducible Llama 3 QLoRA fine-tuning implementation. This release does not train or deploy a model automatically; it establishes safety gates so personal data and GPU time are not consumed by invalid or synthetic training input.

## Detailed changes

### `AUDIT.md`

- Documented source scope, verification results, and prioritized correctness, security, testing, grounding, and fine-tuning findings.
- Flagged the destructive persistent-database E2E fixture and recorded why the full suite was not executed.

### `backend/finetuning/finetune_llama3.py`

- Added JSONL/message/schema validation, placeholder rejection, deduplication, deterministic evaluation splitting, current TRL `SFTConfig` usage, QLoRA configuration, CUDA checks, and a reproducibility manifest.
- Kept heavy ML imports inside the training path so validation and unit tests run without installing GPU packages.

### `backend/finetuning/requirements.txt`

- Added a separate bounded dependency set for training so the FastAPI runtime environment does not need CUDA/ML training packages.

### `backend/finetuning/IMPLEMENTATION.md`

- Added data-quality requirements, commands, evaluation acceptance gates, and the correct adapter-to-Ollama deployment sequence.

### `backend/finetuning/README.md`

- Redirected the workflow through validation and evaluation, replaced the legacy trainer command, and clarified that the registration helper does not convert models to GGUF.

### `backend/tests/test_finetune_llama3.py`

- Added isolated tests for deduplication, deterministic splitting, placeholder rejection, and invalid assistant JSON.

### `.gitignore`

- Excluded personal backend data, generated training datasets/adapters/GGUF files, pytest caches, and TypeScript build metadata from version control.

## Rationale

The pre-existing fine-tuning prototype could ingest fabricated identity data, lacked a holdout set, and used version-sensitive trainer wiring. The new workflow prevents known-bad datasets from starting expensive training and records enough metadata to reproduce and audit each adapter.

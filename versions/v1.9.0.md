# Release v1.9.0 — 2026-09-21

## Overview

Added the post-dataset fine-tuning implementation plan, separating long-running or judgment-dependent manual work from implementation and automation work owned by Codex.

## Detailed changes

### `backend/finetuning/NEXT_STEPS_PLAN.md`

- Defined eight ordered phases covering dataset auditing, baseline measurement, training preparation, QLoRA training, holdout evaluation, Ollama export, application integration, and release monitoring.
- Assigned explicit **CODEX** and **MANUAL** ownership for every phase.
- Added entry/exit gates, measurable safety thresholds, commands, expected artifacts, privacy constraints, and rollback requirements.
- Protected the untouched 30-record holdout set from training or prompt-example use.
- Prioritized dataset factual review before GPU expenditure.

## Rationale

The remaining workflow includes a mix of engineering work and operations that require private-data judgment, external authentication, GPU availability, long downloads, or prolonged computation. Explicit ownership prevents manual work from being mistaken for an implementation gap and keeps all automatable safety work assigned to Codex.

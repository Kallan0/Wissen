# Release v1.7.0 — 2026-09-21

## Overview

Rebuilt the fine-tuning dataset pipeline to require verified personal data, generate diverse role-specific examples through local Ollama, and create deterministic 80/20 training and holdout files.

Generation was attempted for 150 records. It was safely refused because the current knowledge base has no verified candidate name and no work-experience records. The existing `training_data.jsonl` was not overwritten and no incomplete holdout file was created.

## Detailed changes

### `backend/finetuning/dataset_generator.py`

- Removed the synthetic “Alex Chen” profile and all placeholder-contact fallbacks.
- Added fail-fast guards for missing candidate name, verified experience, and verified skills.
- Replaced deterministic fabricated outputs with local Ollama generation grounded in serialized profile data.
- Added round-robin variations for Python Backend Developer, React/Next.js Frontend Developer, and Figma UI/UX Designer roles.
- Added industry/emphasis variations, retry handling, JSON/schema checks, exact-name preservation, bounded dataset size, seeded generation parameters, and atomic output replacement.

### `backend/finetuning/split_dataset.py`

- Added validated, deterministic shuffling with an 80/20 training/holdout split.
- Prevented source/output path collisions and empty splits.
- Writes `training_data.jsonl` and `holdout_eval.jsonl` atomically.

### `backend/main.py`

- Updated the export endpoint to accept 100–200 examples, default to 150, execute long generation outside the event loop, split automatically, and return both download URLs.

### Frontend

- Updated the fine-tuning UI to offer 100, 150, or 200 samples.
- Added separate training and holdout counts and download links.
- Extended the dataset export response type for the split artifacts.

### Tests and documentation

- Added `backend/tests/test_dataset_pipeline.py` for missing-name rejection, missing-experience rejection, and non-overlapping deterministic 80/20 splitting.
- Updated the fine-tuning README with the new generation and splitting commands.

## Verification

- Six fine-tuning/dataset tests passed.
- Python compilation passed for the modified backend and fine-tuning modules.
- Next.js production build and TypeScript checks passed.
- The 150-example generation attempt returned: `Export refused: Verified candidate name is missing from the profile.`

## Rationale

Fine-tuning on invented identities, empty work history, or repetitive project-only examples would reduce model reliability. The pipeline now protects existing datasets and refuses expensive generation until the candidate profile contains the minimum verified evidence.

# v1.19.0 - Collision-Safe Development Startup

Date: 2026-09-24

## Root cause

A stale Next.js development server already owned port `3000`. The original root command used `concurrently -k`, so the frontend's `EADDRINUSE` exit caused the process runner to terminate the otherwise healthy backend and Ollama children.

## Changes

- Replaced the direct root `concurrently` command with `scripts/dev.js`.
- Added `npm run dev:check` for a read-only startup preflight.
- Checks the frontend (`3000`), backend (`8001`), and Ollama (`11434`) before launching children.
- Recognizes and reuses a healthy Wissen frontend, Wissen backend, or Ollama server already listening on its expected port.
- Rejects unknown listeners before starting any service and reports the affected service, URL, and process details when Windows exposes them.
- Starts only missing services while retaining labeled, colored logs and kill-on-child-exit behavior for the services it owns.
- Launches the `concurrently` JavaScript entry point through Node, avoiding Windows `.cmd` shim spawning failures.
- Documented the root startup workflow and port diagnostics in `README.md`.

## Verification

- Reproduced the original collision with a stale Next.js listener.
- Confirmed preflight fails early without starting or killing other services when a listener is unknown.
- Confirmed preflight recognizes and reuses the healthy existing backend.
- Confirmed the repaired root command starts the missing frontend and Ollama services.
- Frontend: HTTP `200` on port `3000`.
- Backend: `/api/health` returned `healthy` on port `8001`.
- Ollama: `/api/version` returned `0.31.1` on port `11434`.

## Log clarification

Ollama's failed calls to its cloud model-recommendation endpoints are warnings caused by restricted outbound networking. They do not prevent the local Ollama API or installed local models from working.

# v1.21.0 - Selectable Groq Cloud and Ollama Inference

Date: 2026-10-28

## Summary

Added optional Groq Cloud inference so resume and role-generation workloads can run without loading a model on the workstation GPU, while retaining Ollama as the offline/local provider.

## Backend

- Added server-side Groq Chat Completions integration using the existing async `httpx` client.
- Uses Groq's OpenAI-compatible `/openai/v1/chat/completions` endpoint with JSON response mode.
- Keeps `GROQ_API_KEY` entirely in the backend environment and never returns it through an API response.
- Namespaces cloud selections as `groq::<model>` and enforces a configured model allow-list.
- Supports `GROQ_BASE_URL`, `GROQ_DEFAULT_MODEL`, `GROQ_MODELS`, and `AI_DEFAULT_PROVIDER`.
- Added `.env` loading with real process environment variables taking precedence.
- Added `OLLAMA_ENABLED=false` cloud-only mode. The root launcher skips Ollama and the backend does not offer local models in that mode.
- A Groq failure uses the deterministic ChromaDB fallback rather than silently starting local GPU inference.
- Retries one HTTP 429 response using Groq's `retry-after` header, capped at five seconds.
- Health responses expose Groq configured/online state without secrets.

## Frontend

- Model selectors distinguish `Groq Cloud` from `Ollama Local`.
- Cloud selections visibly disclose that the JD and retrieved verified profile context leave the device.
- The navigation telemetry reports Groq readiness and whether Ollama is disabled.
- Updated application copy to accurately describe selectable cloud/local inference.

## Configuration

- Added `.env.example` with safe placeholders.
- For no Ollama/GPU startup, set `GROQ_API_KEY`, `AI_DEFAULT_PROVIDER=groq`, and `OLLAMA_ENABLED=false` in the ignored root `.env`.
- Set `OLLAMA_ENABLED=true` to expose both cloud and offline choices.

## Verification

- Provider, rendering, and profile tests: 12 passed.
- Health/model endpoint integration tests: 3 passed.
- Next.js production build passed; first-load JavaScript remains approximately 115 kB.
- Added coverage for key enforcement, model allow-listing, request structure, provider ordering, and cloud-only selection.

## Privacy boundary

Local ChromaDB storage remains on-device. When Groq is selected, the backend transmits the target job description, relevant retrieved candidate context, and generation instructions to Groq. Users who require device-only processing must select Ollama.
